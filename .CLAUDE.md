# Agent startup notes

How work is done here, and the constraints agents have repeatedly broken. For the codebase itself,
start from `fhevm-npm-docs` folder. Do not grow this file with content another doc already owns.

## How we work

The skills named below live in [.claude/skills](.claude/skills).

### Rules

- Always follow the rules in `fhevm-npm-docs/FHEVM_NPM_RULES.md`: that file holds this repository's numbered rules.
- If a rule or guidance listed in `fhevm-npm-docs/FHEVM_NPM_RULES.md` must change or be modified, always ask for approval.
- References to `fhevm-npm-docs/FHEVM_NPM_RULES.md` in code comments must never be stale.
- Additional deployments rules are listed in: [deployments/README.md](deployments/README.md)

### Design

- When part of the code or docs is subpar, delete it and rewrite it. Do not patch around it.
- Build only what was asked for. No speculative flags, options or layers. Remove the ones you find.

### Docs and prose

- Keep docs short and readable by a human: the high-level view and the instructions. The code holds
  the details. Each fact has one home.
- Write with `/technical-writing`, draw with `/show-me`, then run `/unslop` over the result.

### Before opening a PR

Review the branch diff with independent subagents, run in parallel, and address what they find. The
reviewers report; the main agent applies the fixes.

- `/thermo-nuclear-code-quality-review`: structure,
  abstractions, TypeScript and Effect usage, dead code.
- `/technical-writing` then `/unslop`: docs touched by the change.

Check every reference to a rule of `fhevm-npm-docs/FHEVM_NPM_RULES.md`: it must cite the right rule
number and match that rule's current text.

The title is a conventional commit, `type(scope): summary`. Write the body with `/technical-writing`
and `/show-me`: the change at the architecture level, then everything that must happen before merge
and publish (secrets, npm and ghcr publishing, manual operations). That list must be complete.
