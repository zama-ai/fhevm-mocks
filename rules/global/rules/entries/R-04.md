Each generation is written on its own release branch. After a rotation, the repository keeps a copy of the previous generation, and that copy stays byte-identical to its release branch, except for the files the rotation deleted. An edit to the copy makes the upgrade tests run against a stack that nobody ships. [NR-27](../../../fhevm-npm/rules/entries/NR-27.md) states the same rule for the npm workspace, and the two evolve separately.
