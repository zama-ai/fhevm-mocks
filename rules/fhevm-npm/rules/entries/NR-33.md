Within one
`dependencyGroup`, every `dev`, `shared-helper` and `internal-consumer` package declares the same range for a
dependency they share: they build against one hoisted copy, so a different range fails only the day a member is
installed alone. Members are compared with each other, not with a table, so a new group needs no edit. A [NR-15](NR-15.md)
`file:` link counts by the directory it resolves to, so siblings at different depths agree when they link the same
member. Two kinds in a group are bounded instead of compared: a published payload states the range its users may
have, and a standalone consumer, installed alone, may declare any version or range inside it.

```jsonc
// ✅ Installed together: hardhat/v3/plugin, hardhat/v3/e2e and the template agree.
"hardhat": "^3.20.0"

// ✅ The published hardhat/v3/plugin/pkg states what its users may have.
"peerDependencies": { "hardhat": "^3.0.0" }

// ✅ The standalone hardhat/v3/plugin/test-consumer/esm pins a version inside that peer range.
"hardhat": "3.15.0"

// ❌ hardhat/v3/e2e next to the plugin's ^3.20.0: one hoisted copy, two claims.
"hardhat": "^3.18.0"

// ❌ A standalone consumer outside the published peer range proves nothing a user can install.
"hardhat": "2.29.1"
```
