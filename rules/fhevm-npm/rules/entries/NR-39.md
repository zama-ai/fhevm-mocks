The
first sits outside every `workspaces` list, so every version it needs is declared in its own manifest and frozen in its
own lockfile; a private one still repeats the workspace root's spec for every root-declared package it declares ([NR-31](NR-31.md)),
so it declares what the workspace declares: the version the workspace pins, or the same range, which its own lockfile
resolves. The second is directory-local metadata; installable behavior belongs in a real package.

```jsonc
// ✅ A private consumer fixture states every version itself, and repeats the root's spec for what the root declares.
"dependencies": { "viem": "2.55.19" }, "devDependencies": { "typescript": "^6.0.3" }

// ❌ A private fixture choosing its own spec for a package the root declares.
"devDependencies": { "typescript": "^5.9.3" }

// ❌ A non-package with dependencies. Nothing can depend on it — it has no `name` — so
//    whatever is declared here is installed for a package that does not exist.
{ "type": "module", "private": true, "devDependencies": { "typescript": "^6.0.2" } }
```
