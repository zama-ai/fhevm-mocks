A rotation is a change that a person reviews: a new `<vN>` directory, the `previous` and `current` entries of `npm-manifest.json#generations`, and every dependency spec that moves from `<vN-1>` to `<vN>`. The developer makes all of it, by hand or with a command written for that purpose, and the diff of the pull request shows each edit.

A check never makes any of it. It reads the workspace and reports what breaks a rule. If a check fixed a pin or moved a directory itself, the fix would land without review, and a wrong fix would hide the very problem the check exists to report.

## Examples

- ✅ The developer adds `host-contracts-cleartext/<vN>`, moves `current` and `previous` in the manifest, and edits each pin. `fhevm-npm check generations` then reports every pin that still targets `<vN-1>`.
- ✅ A command made to write, such as `fhevm-npm generate cleartext-config`, writes its files when the developer runs it, and the developer commits the result.
- ❌ A check that finds a pin on `<vN-1>` and rewrites it to `<vN>` before it reports success.
- ❌ A check that creates a missing generation directory so that its own test passes.

`fhevm-npm check package-json` with its sort option is not an exception: it reorders the fields of a `package.json` only when the developer asks for it, and changes no value.
