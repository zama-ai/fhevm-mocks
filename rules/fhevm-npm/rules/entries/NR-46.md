- **Policy:** the workspace root holds the one `eslint.base.mjs`. It sets which rules apply and at what severity,
  and names no package path.
- **Entry:** every non-published package that defines `lint` contains `eslint.config.js`. It is the only file
  ESLint loads, and the only ESLint config filename allowed in a package. A dev owner that contains only
  `package.json` and `pkg/` has no ESLint config.
- **Layout:** which directories get which rules. A package states its layout in its own `eslint.config.js`. When
  two or more packages share the same layout, it may live once in a shared module, `<family>/eslint.<name>.mjs`.
  The module sits in the common parent folder of those packages, outside every package. It imports
  `eslint.base.mjs`, gives paths only, sets no rule, and is imported by each `eslint.config.js` that uses it, all
  of them below its folder. It is `.mjs` because the nearest `package.json` declares no `type`.
- **Local:** what belongs to one package only stays in its `eslint.config.js`: its own ignores, and a rule turned
  off for named files, with a comment that says why.

```text
✅ eslint.base.mjs                        policy
   <family>/eslint.<name>.mjs            layout shared by <family>/<vN>
   <family>/<vN>/eslint.config.js        entry + local
❌ <family>/<vN>/eslint.layout.mjs        a layout module inside a package
❌ <family>/eslint.<name>.mjs             imported by one package only: inline it
❌ eslint.config.mjs, .eslintrc.json      not the entry filename
```
