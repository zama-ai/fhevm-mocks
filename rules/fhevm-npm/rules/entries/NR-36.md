  - "Gap, loose check: Set a mirror-only published payload's central and derived package version to 1.0.0-01. The version parser and JSON schema both accept the numeric prerelease identifier with a leading zero; isCanonicalVersion returned true in memory. Using a mirror-only payload avoids relying on npm pack's separate version validation, since published-files skips that payload. Fix: issue I-91."

Exactly one entry per
`kind: published` manifest package, keyed by its manifest key (names are not unique: two generations share
`@fhevm/host-contracts-cleartext`), listed in manifest order, every value canonical SemVer (`x.y.z` or `x.y.z-pre`).
`fhevm-npm version check` enforces coverage both ways (`version-coverage`), the value shape (`version-semver`) and the
order (`version-order`); it runs in `check-pre`. A missing entry is never inferred from a package's `package.json`,
because that would let derived state become authoritative — it is added by hand, once.

```jsonc
// ✅ versions.json: the manifest's published payloads, in the manifest's order.
{ "schemaVersion": 1, "packages": { "./host-contracts-cleartext/<vN>/pkg": "<N>.0", "./hardhat/v3/plugin/pkg": "<N>.0" } }

// ❌ A range, and a payload the manifest does not publish.
{ "packages": { "./hardhat/v3/plugin/pkg": "^<N>.0", "./hardhat/v3/e2e": "0.0.0" } }
```
