title: Event folders are numbered
short: An event folder is named `<seq>-<deploy|upgrade|hotfix>-v<release>-<YYYY-MM-DD>`, with a sequence that starts at `00` and has no gap.
old: "8.1.2"

evidence:
  - "Gap, loose check: `fhevm-npm/base/checks/deployments.ts:346-357` accepts any journal transaction between `first` and `last` as an upgrade's or hotfix's `defining`; it never checks that it is the `ACLOwner.upgrade` transaction. Fix: check it (issue I-67)."

`<seq>-<deploy|upgrade|hotfix>-v<release>-<YYYY-MM-DD>`, the sequence
contiguous from `00`, exactly one `deploy`, first. `v<release>` is the package version the tool ran at, without the
major below 1.0 (`v14.1` is 0.14.1) and with it from 1.0 on (`v1.0.0`); the date is the UTC day of the block holding
the event's defining transaction (an upgrade's or hotfix's `ACLOwner.upgrade`, a deploy's last transaction), as
recorded in the `event.json` of the folder the config's `outDir` names. For now, a deploy without `event.json` ([NR-79](NR-79.md))
has no recorded block day, so its date is held only to the order of dates ([NR-82](NR-82.md)).

> **Implemented.** `fhevm-npm check deployments` checks this rule. It runs in `make check-pre`, and it is generation-free.
