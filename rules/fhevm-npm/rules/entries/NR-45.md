It contains `prettier.config.js` re-exporting the workspace root's `prettier.base.mjs` by relative
path; the only accepted config filenames are those two. A dev owner containing only `package.json` and `pkg/` has no
local source to format, so any local Prettier config is forbidden. An installation root carries neither. Two packages
are spared the re-export. A mirror-only payload's dev owner need not carry it. A package at `<owner>/pkg` whose parent
`<owner>` is an inventoried package whose name ends in `-dev`, such as a workspace-native template, contains its own
`prettier.config.js` instead: users receive that template on its own, so `fhevm-npm check scripts` fails
a Prettier or ESLint config in it that imports, by a literal specifier, a workspace-only package or a relative or
absolute path that resolves lexically outside it. The check is static: it does not see a computed import or a URI
specifier such as `file:`, and it does not follow symlinks, so it is no proof that the config is self-contained at run
time.

**The workspace root is the sole exception: it holds both, and both are required.** `prettier.base.mjs` is the shared
base, and `prettier.config.js` re-exports it. The second is not a duplicate: `prettier.base.mjs` is not a filename
Prettier discovers, so the files that sit directly in the workspace root and belong to no package — `npm-manifest.json`,
`cleartext-config.json`, the root-level docs — are formatted with the shared base only through that re-export. Two
configs are allowed here; two sources of formatting truth are not, so the re-export is pinned to the one statement.

Comments are ignored when the statement is pinned, in every package: prose explaining a config is not a fork of it.

```js
// ✅ In an ESM common/prettier.config.js.
export { default } from '../prettier.base.mjs';

// ✅ In a CommonJS package's prettier.config.js.
module.exports = import('../../../prettier.base.mjs').then((module) => module.default);

// ✅ At the workspace root, beside prettier.base.mjs, comment and all.
export { default } from './prettier.base.mjs';

// ✅ In a template at <owner>/pkg under a `…-dev` owner: self-contained, nothing imported from the workspace.
export default { singleQuote: true, printWidth: 120 };
```

```text
❌ Alternate configuration filename:
.prettierrc.mjs

❌ At the workspace root, restating options instead of re-exporting the base:
export default { singleQuote: true };
```
