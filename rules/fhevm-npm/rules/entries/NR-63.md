`file:` links
are right in the tree ([NR-15](NR-15.md)) and wrong on npmjs.com, which cannot resolve a path; `fhevm-npm publish pack` is the only
producer of a tarball, and it renders every link per [NR-38](NR-38.md) into a staged copy before `npm pack`, so the tree is never
touched. `fhevm-npm publish check <payload>` reads the tarball with `tar` and fails on any surviving `file:` spec, a
version other than the central one, a dependency on another payload whose range is not what that payload's
central version renders to, or an entry point the shipped `package.json` declares (`main`, `module`,
`types`, `bin`, any `exports` leaf) that the tarball does not contain — `files` is a whitelist, so a built
entry point left out of it publishes a package that resolves to nothing, and the `publint`/`attw` gate of
[NR-61](NR-61.md) inspects the payload directory rather than this artifact. With `--check-npmjs` it also requires every rendered range to
have a published satisfying version — retried, because the previous release job publishes the dependency moments earlier
— and the payload's own version to be absent, never retried. `fhevm-npm publish order` derives a sequence from the
links. The release workflow writes a dependency order down by hand, as one job per payload, each waiting for the one
before; nothing checks it against `publish order`. In a real release the order is still enforced by refusal, since each
job's `publish check --check-npmjs` refuses a payload whose dependency is not on npmjs.com yet. Before the first job,
`fhevm-npm publish rehearse` packs every payload of the release set into the tarballs directory and checks them
together, in publish order, a dependency inside the set being satisfied by its freshly packed tarball, so a payload a
later job would refuse stops the release before anything is published; `make publish-rehearse` runs the same rehearsal
on a developer machine. `publish render <payload>` shows the same rendering without producing anything.

```sh
# ✅ Before any job publishes: the whole release set packed and checked together.
# The excluded payload key is illustrative.
fhevm-npm publish rehearse --exclude "./example-owner/pkg"

# ✅ Then one job per payload $p, in the workflow's dependency order, each payload proven just before it goes out.
tgz=$(fhevm-npm publish pack "$p")
fhevm-npm publish render "$p"
fhevm-npm publish check "$p" --check-npmjs
npm publish "$tgz"

# ❌ Publishes the working tree: the tarball ships "file:../../../../host-contracts-cleartext/<vN>/pkg".
npm publish ./hardhat/v3/plugin/pkg
```
