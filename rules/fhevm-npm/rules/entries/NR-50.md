A consumer can
compile while TypeScript falls back to shipped source or resolves the payload's sources in the checkout instead of the
installed declarations. For each installed published payload that declares a root entry point and types, `test-consumer`
therefore runs `tsc --traceResolution` on a one-line import of the package, fails if that import does not compile, and
proves two things: the trace names a declaration the installed `package.json` declares (`types`, `typings` or a `types`
condition of `exports`), and no `.ts` module resolves from the payload's directory in the workspace. The probe resolves
under `nodenext`, whatever the consumer's own mode: a `.cts` file selects CommonJS and a `.mts` file ESM, once per
module format the consumer uses and the payload exposes. A consumer whose installation has no `typescript` skips the
probe. `test-consumer` compiles nothing else itself: any other compilation is the fixture's own `test` script's, and the
Hardhat v2 template's `hardhat test` does not type-check, so in `test-consumer` the probe is that consumer's only
declaration check. The probe does not trace a legacy mode such as `node10`: the option is deprecated from TypeScript 6
and its opt-out value differs per major, so no generic check can pin it. The Hardhat v2 plugin's own test traces
`node10` instead (`hardhat/v2/plugin/test/node10-cjs-resolution.test.ts`, run by `make test-hh-v2-plugin`), against its
symlinked `pkg/` rather than an isolated installation.

```text
✅ /tmp/fhevm-consumer-abc123/node_modules/@fhevm/hardhat-plugin/_types/index.d.ts
❌ /repo/hardhat/v2/plugin/pkg/src/index.ts
❌ /tmp/fhevm-consumer-abc123/node_modules/@fhevm/hardhat-plugin/src/index.ts  (caught when the trace then names no declared file)
```
