title: Ship the license and the front page
short: Every published package carries the repository license, and every npm-distributed payload also carries its front page.
old: "5.2.7"
check: script
evidence:
  - "Gap, loose check: In the mirror-only payload hardhat/v2/fhevm-hardhat-template/pkg, replace LICENSE by a symlink to ../../../../LICENSE: existingFile() uses statSync, which follows the link, so the 'regular file' test passes, and published-files.ts skips mirror-only payloads; the mirror then receives a dangling link. On a case-insensitive disk a file named `license` also passes there, but the Linux CI catches that one. Narrow: an npm-distributed payload is safe because npm does not pack a symlink and 5.2.6 then reports it. Fix: issue I-106."

- Every published package sets `"license": "BSD-3-Clause-Clear"` exactly in its `package.json`, and a regular
  file named exactly `LICENSE` sits beside that `package.json`. The field supports registry metadata; the file
  ensures the payload carries the license text.
- An npm-distributed payload also has `README.md` in the payload directory, and names both `LICENSE` and
  `README.md` in `files`. They are the two files npmjs.com renders on a package page: the license text and the
  front page. npm packs both whatever `files` says, so the listing exists for the reader, not for npm: a whitelist
  that omits them reads as if the package shipped without them.
- Names are exact: `LICENSE` and `README.md`, not `license` or `readme`.

```jsonc
// ✅ The whitelist is the complete manifest of what ships.
"files": ["src", "_types", "LICENSE", "README.md", "!**/tsconfig*.json"]

// ❌ Both files sit in pkg/ and npm packs them, yet the list says otherwise.
"files": ["src", "_types", "!**/tsconfig*.json"]
```
