The `.` root's `package.json` is the one place a
shared spec is declared: the dependency checks compare packages with its specs alone, whichever installation root
installs them. Each installation root hoists its own copy: a member of the `.` root compiles against the `.` root's, and
a member of a cluster root such as `hardhat/v2` against its cluster's. For an exact pin, that copy is the pinned version
because the member repeats the root's spec ([NR-31](NR-31.md)); for a range, each installation root resolves its own version inside
the same range. These root-spec checks do not compare the resolved versions; a dependency pinned in
`npm-manifest.json#dependencies.pinned` still has every resolved copy held to its pin ([NR-21](NR-21.md)). Either way, a member
declaring something else publishes a claim nobody verified.

```jsonc
// ✅ In the workspace root's package.json. Exact, because these are the two whose ranges already diverged once.
"devDependencies": { "ethers": "6.17.0", "viem": "2.55.19" }

// ❌ No root pin, so every member states its own, and the installation roots lose their shared declaration
//    baseline: each resolves whatever its own members happen to declare.
"devDependencies": {}
```
