---
id: NR-31
tag: GAP
group: Dependencies
title: Private packages repeat the root spec
short: A private workspace package declares every exact root pin it directly uses, and every private package repeats the root's spec for each root dependency it declares.
old: "4.2.1"
check: script
evidence:
  - "Gap, wrong check: the 4.2.1 placement test in `fhevm-npm/base/checks/dependencies.ts` counts a script that runs an exact root pin's executable as a use, and asks a shared helper for `dependencies`; 3.3.1 asks for `devDependencies`. Fix: ignore script-only use in the 4.2.1 placement test, so `devDependencies` wins."
issues:
  - I-01
  - I-58
---

The spec is repeated verbatim: an exact root pin exactly, a
ranged root spec with the same range. A different spec would claim support for a version the workspace did not test. Use
and placement are judged under this rule for an exact root pin only, on a `dev`, `shared-helper` or `internal-consumer`
package: a package whose own source files import the dependency, or whose npm scripts run one of its executables,
declares it, and a package that does neither does not declare it. Shared helpers use `dependencies` (importing them must
install their runtime requirements); dev owners and internal consumers use `devDependencies`, because neither ships as a
runtime package. A root dependency whose executable a script runs must be declared whatever the root's spec, in
`devDependencies`, under [NR-18](NR-18.md). For a shared helper whose script runs an exact root pin's executable, `devDependencies`
wins: a tool that only a script runs is not a runtime requirement of the helper. A private `standalone` fixture is held
to the verbatim match alone, for the root dependencies it declares.

```jsonc
// ✅ The workspace root's package.json is the version source of truth: one exact pin, one range.
"devDependencies": { "ethers": "6.17.0", "example-linter": "^3.1.0" }

// ✅ A private consumer imports ethers (4.2.1) and runs example-linter (3.3.1), so its manifest declares both,
//    each with the root's spec.
"devDependencies": { "ethers": "6.17.0", "example-linter": "^3.1.0" }

// ✅ common is a shared helper whose exported runtime imports viem.
"dependencies": { "viem": "2.55.19" }

// ❌ Missing: this package imports ethers but relies silently on the root's hoisted copy.
"devDependencies": {}

// ❌ A range is not the exact version the private package actually tests.
"devDependencies": { "ethers": "^6.17.0" }

// ❌ A different floor makes a claim the workspace does not verify.
"devDependencies": { "ethers": "^6.16.0" }

// ❌ Not the root's range: a ranged root spec is repeated verbatim too.
"devDependencies": { "example-linter": "^3.0.0" }

// ✅ Published payloads remain ranges whose floor matches the pin, as required by 4.3.1.
"peerDependencies": { "ethers": "^6.17.0" }
```

`fhevm-npm check dependencies` compares each private package's declarations with the root's specs and, for an exact root
pin, with what the package uses (the bare imports of its owned source files and the executables its npm scripts invoke),
keyed by the manifest inventory, and reports `4.2.1` on a missing, unused, misplaced or divergent declaration. Published
entries stay under [NR-35](NR-35.md); non-packages, and whatever a standalone project declares beyond the root's specs, under [NR-39](NR-39.md).
