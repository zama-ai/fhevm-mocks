For each published payload a
fixture links, `test-consumer` resolves it by name in each module format the consumer uses and the payload exposes
([NR-60](NR-60.md)), and traces its declarations under `nodenext` when the conditions of [NR-50](NR-50.md) hold. A `nodenext` trace does not
prove a legacy mode: `node10` ignores `exports` and uses legacy package resolution, so substituting one for the other
proves a different package. Hardhat v2 consumers use `node10`. The isolated Hardhat v2 consumer has no `node10` proof:
the plugin's own test holds the only `node10` declaration trace ([NR-50](NR-50.md)), and `attw --pack` adds a static `node10`
verdict ([NR-51](NR-51.md)).

```jsonc
// ✅ Hardhat v2's TypeScript consumer profile. Under TypeScript 6, the plugin's test also sets
// "ignoreDeprecations": "6.0".
{ "module": "commonjs", "moduleResolution": "node10" }

// ❌ As proof of that profile: test-consumer's probe proves nodenext, not node10 (5.2.4).
{ "module": "nodenext", "moduleResolution": "nodenext" }
```
