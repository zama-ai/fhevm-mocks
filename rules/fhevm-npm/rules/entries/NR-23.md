---
id: NR-23
tag: HOLD
group: Generations
title: Vendored copies cover exactly the live generations
short: Every vendored destination under a generation family sits in a live generation, and every live generation is among the directories that receive a face.
old: '3.4.2'
check: script
checked-by: './fhevm-npm-cli check generations'
---

A copy of `common-vendored/src` is declared on its destination package's
`vendored` entry in `npm-manifest.json` ([NR-42b](NR-42b.md)), and nowhere else. The check reads the destinations back out of those
entries: the entries with a local `source` that carry the same `files` under the same `rewrites` and `renamed` form one
destination; an entry pinned to an upstream origin is no part of one. A destination's `to` lists every directory that
receives its files. That grouping is what lets the check ask whether every live generation is among them. Each path
below the family directory must be under `<vN>` or `<vN-1>`. A path left under a retired generation is the entry a rotation
forgets, and it makes `fhevm-npm sync vendored` write into a generation nothing depends on. The converse half matters
more: a live generation missing from a destination, because its payload carries no such entry, receives no copy and no
byte comparison, so its committed copy drifts from `common-vendored/src` unnoticed — the exact failure that file exists
to prevent. One destination writes one face, so its entries must sit at the same path below their generation directory;
that is what lets a missing generation be named as the entry to add. A destination whose family paths are all retired is
reported only as something to retarget.

The one exception is a face NAMED for a generation, `<name>-<gen>.<ext>` by its SOURCE name — for
example `cleartext-config-<vN>.ts`, the complete TypeScript face rule [NR-42c](NR-42c.md)'s generator emits for <vN>, which lands in <vN>'s
pkg/ts `renamed` to the stable `cleartext-config.ts`. It exists for one generation by construction, so it is not
demanded of the others; what is demanded is the converse, that it lands in the generation it is named for and nowhere
else, and that it travels in an entry of its own. <vN>'s face copied into <vN-1> would hand <vN-1> constants its contracts
have no field for.

```jsonc
// Entries of npm-manifest.json#packages, their other fields left out.
// ✅ One face, the same entry on both live generations' payloads.
"./host-contracts-cleartext/<vN>/pkg":   { "vendored": [{ "relPath": "./ts/types", "files": ["shared.ts"], "source": "./common-vendored/src", "reason": "…" }] }
"./host-contracts-cleartext/<vN-1>/pkg": { "vendored": [{ "relPath": "./ts/types", "files": ["shared.ts"], "source": "./common-vendored/src", "reason": "…" }] }

// ✅ <vN>'s face lands in <vN> alone, in its own entry, under the stable name.
"./host-contracts-cleartext/<vN>/pkg": { "vendored": [{ "relPath": "./ts", "files": ["cleartext-config.ts"], "renamed": { "cleartext-config.ts": "cleartext-config-<vN>.ts" }, "source": "./common-vendored/src", "reason": "…" }] }

// ❌ <vN>'s face copied into <vN-1> too: values <vN-1>'s contracts have no field for.
"./host-contracts-cleartext/<vN-1>/pkg": { "vendored": [{ "relPath": "./ts", "files": ["cleartext-config.ts"], "renamed": { "cleartext-config.ts": "cleartext-config-<vN>.ts" }, "source": "./common-vendored/src", "reason": "…" }] }

// ❌ After the pair rotates to <vN+1>/<vN>: only <vN>'s payload carries the entry. <vN+1>, the new current generation, is missing, so it silently keeps a stale copy.
"./host-contracts-cleartext/<vN+1>/pkg": { /* no entry for shared.ts */ }
"./host-contracts-cleartext/<vN>/pkg":   { "vendored": [{ "relPath": "./ts/types", "files": ["shared.ts"], "source": "./common-vendored/src", "reason": "…" }] }

// ❌ <vN-2> is retired: the entry sits on a generation `generations` no longer lists.
"./host-contracts-cleartext/<vN-2>/pkg": { "vendored": [{ "relPath": "./ts/types", "files": ["shared.ts"], "source": "./common-vendored/src", "reason": "…" }] }

// ❌ One set of files, two faces: which face is a missing generation owed?
"./host-contracts-cleartext/<vN>/pkg":   { "vendored": [{ "relPath": "./ts", "files": ["x.ts"], "source": "./common-vendored/src", "reason": "…" }] }
"./host-contracts-cleartext/<vN-1>/pkg": { "vendored": [{ "relPath": "./ts/types", "files": ["x.ts"], "source": "./common-vendored/src", "reason": "…" }] }
```
