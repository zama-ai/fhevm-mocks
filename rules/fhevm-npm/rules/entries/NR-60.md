  - "Gap, loose check: A valid bare main path ('index.js') is filtered by declaredEntryPoints; absent other prefixed entries, the runner incorrectly treats the package as having no root and skips name resolution entirely. Fix: issue I-110."

  - I-110

For each published payload the fixture links
that declares a root entry point, `test-consumer` resolves the package name from the temporary consumer with the
consumer's own module system, `require.resolve` for CJS and `import.meta.resolve` for ESM, once per module format the
consumer uses and the payload exposes. It fails unless the resolved file lies inside the installed package and is an
entry point the installed `package.json` declares. It then traces the declarations by the same name ([NR-50](NR-50.md)) and, with
`--run`, runs the fixture's `test` script, the real consumer suite (`test:file` instead, with `--test-file`). A relative
import bypasses package resolution, so `test-consumer` resolves the name itself and does not rely on the fixture's
imports. A relative import into the checkout also fails when the temporary copy runs its suite ([NR-56](NR-56.md)).

```ts
require('@fhevm/hardhat-plugin'); // ✅ Exercises the installed manifest, exports and files.
require('../../plugin/pkg/src/index'); // ❌ Reaches source directly and proves nothing about the installed package.
```
