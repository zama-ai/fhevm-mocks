tag: GAP
group: Deployments
title: Each event links to the one before
short: Every event except a deploy links to the manifest of the event before it, by path and sha256.
old: "8.3.2"
check: script
checked-by: "./fhevm-npm-cli check deployments"
evidence:
  - "Gap, wrong check: `fhevm-npm/base/checks/deployments.ts:646-648` finds an attempt's target by exact path, so an attempt that links through a byte-identical copy in its own folder fails before the copy allowance runs. Fix: find the target by the copy's sha256 (issue I-59, decision D15)."
issues:
  - I-10
  - I-59
  - I-68
---

A deploy has no `previous`. Every other event's manifest has
`previous.path` resolving to the previous event's manifest, `previous.sha256` equal to that file's bytes, and
`previous.deploymentId`, `chainId`, `version`, `packageVersion` equal to it. An attempt links the same way to the event
it started from. The sha256 is the link and the path only says where those bytes are, so the path may instead resolve to
a copy of that manifest kept inside the event's own folder, provided its bytes are identical: what an operator's seal says
when `previousManifest` pointed at a copy. A seal is never rewritten ([NR-84](NR-84.md)), so such an event could not otherwise be
archived. Through such a copy, and only there, `previous.packageVersion` may be absent when the previous manifest has
none: the folder name that stands for it was out of the tool's sight.

> **Implemented.** `fhevm-npm check deployments` checks this rule. It runs in `make check-pre`, and it is generation-free.
