This includes packages imported by
source files and tools invoked by npm scripts; script-only tools belong in `devDependencies`. A package resolved only
through hoisting is a phantom dependency: it disappears under a different install strategy, and non-node tools never
find it at all.

```jsonc
// ✅ hardhat/v2/e2e imports chai and hardhat-ethers in its tests, so it declares both.
"devDependencies": { "@nomicfoundation/hardhat-ethers": "^3.1.3", "chai": "^4.5.0", "hardhat": "^2.29.1" }

// ❌ The same imports, undeclared. They resolve only because another member's copies sit hoisted in the
//    installation root's node_modules.
"devDependencies": { "hardhat": "^2.29.1" }

// ✅ A script invokes eslint, and the package declares the tool itself.
{ "scripts": { "lint": "eslint" }, "devDependencies": { "eslint": "^10.13.0" } }

// ❌ eslint happens to be hoisted from the workspace root but is undeclared here.
{ "scripts": { "lint": "eslint" } }
```

> On `release/0.14.x`, `hardhat/v3/plugin/test/deploy.test.ts:8` imports `@fhevm/host-contracts-cleartext/ts`, which
> `hardhat/v3/plugin/package.json` does not declare; `fhevm-npm/base/checks/dependencies.ts:31-50` compares source
> imports only with root pins. Fix: issue I-53, pushed on a branch, not yet merged.
