A live generation is a generation of a [generation family](ND-01.md) that `npm-manifest.json#generations` names for that family. The manifest names the directory of each one: `current` is `<vN>`, the generation that every consumer depends on, and `previous` is `<vN-1>`, kept so that the upgrade from `<vN-1>` to `<vN>` can be built and tested. A generation that the manifest no longer names is retired.

## Examples

```jsonc
// ✅ Two live generations: current and previous.
"current": "./host-contracts-cleartext/<vN>",
"previous": "./host-contracts-cleartext/<vN-1>"
```

- ✅ After the rotation that brings in `<vN>`, `<vN>` and `<vN-1>` are the live generations of `host-contracts-cleartext`.
- ❌ `<vN-2>` is not live. The manifest no longer names it, so it is retired. A list that names the live generations, as the cleartext config of [NR-24](../../rules/entries/NR-24.md) does, never names `<vN-2>`.
- ❌ A directory that exists on disk is not live for that reason alone. Only the manifest makes a generation live.

## Live on chain

In the npm workspace, a generation is live when the manifest names it, as above. Outside the workspace, "live" also means that a network runs it: a generation is live on chain on each network whose host contracts are at that generation. The two meanings follow different clocks:

- Liveness on chain is per network. A generation can be live on one network and dead on another.
- The workspace rotates when the developer starts the next generation, not when a network deploys one, as [NR-87](../../rules/entries/NR-87.md) says. So `current` can be live in the workspace before any network runs it.
- A generation that the workspace has retired can still be live on chain, on a network that has not upgraded yet.
- A generation that runs on no network any more is dead on chain for good.

Examples:

- ✅ Work on `<vN+1>` starts while testnet does not run `<vN>` yet. The workspace rotates anyway: `<vN+1>` is `current` and `<vN>` is `previous`, live in the workspace although no network runs either of them yet.
- ✅ After that rotation, mainnet can still run `<vN-1>`. `<vN-1>` is retired from the workspace and still live on chain on mainnet.
- ❌ Protocol v12 was retired from every network. It is dead on chain for good, and no workspace names it.

## What can change

This definition follows the way the protocol rotates its generations. If the protocol design changes how many generations stay side by side, or how the manifest names them, which generations are live can change too.
