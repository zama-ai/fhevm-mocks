An npm-distributed payload is a [published package](ND-03.md) that reaches npmjs.com. Its `distribution` in `npm-manifest.json` includes `npm`, or is omitted, which means npm.

Being npm-distributed depends only on `distribution`. A published package can also be kept in sync with a Git repository through the `mirror` field of the manifest, and still be npm-distributed.

## Examples

- ✅ `hardhat/v2/plugin/pkg`, published as `@fhevm/hardhat-plugin`. Its entry has no `distribution`, so npm distributes it.
- ✅ `foundry/forge-fhevm-std/pkg`, published as `@fhevm/forge`. Its entry has no `distribution`, so npm distributes it. It ships only Solidity sources, and is npm-distributed all the same.
- ✅ `host-contracts-cleartext/<vN>/pkg`, published as `@fhevm/host-contracts-cleartext`. Its entry has a `mirror` and no `distribution`, so npm distributes it, and the mirror does not change that.
- ❌ `hardhat/v2/fhevm-hardhat-template/pkg`. Its `distribution` is `["mirror"]`, so it is published but not npm-distributed.

## What can change

This definition follows the `distribution` field of the manifest schema. If the schema changes how it names the npm channel, or the default when `distribution` is omitted, this definition changes with it.
