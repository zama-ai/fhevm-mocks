A published package is a package that leaves the workspace. `npm-manifest.json` gives it the kind `published`, and its `distribution` names the channels through which it leaves: `npm`, `mirror`, or both. A published package with no `distribution` goes to npm only.

A published package does not always reach npmjs.com. A published package whose only channel is `mirror` is mirror-only: it reaches users through a public Git repository and never through npm. [ND-04](ND-04.md) defines the published packages that npm distributes.

## Examples

```jsonc
// ✅ Published, through npm: no distribution means npm.
"./hardhat/v2/plugin/pkg": { "kind": "published", "name": "@fhevm/hardhat-plugin" }

// ✅ Published, mirror-only: it never reaches npmjs.com, and it is still published.
"./hardhat/v2/fhevm-hardhat-template/pkg": {
  "kind": "published",
  "name": "fhevm-hardhat-template-v2",
  "distribution": ["mirror"]
}

// ❌ Not published: a dev package stays in the workspace, even when it wraps a published package.
"./hardhat/v2/plugin": { "kind": "dev", "publishedRelPath": "./hardhat/v2/plugin/pkg" }
```

## What can change

This definition follows the channels that the manifest schema allows in `distribution`. If the schema adds a channel, a published package can leave the workspace through it too.
