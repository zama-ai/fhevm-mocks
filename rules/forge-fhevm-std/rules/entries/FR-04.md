`foundry/forge-fhevm-std` and its `pkg/` are
in the sdk root's `workspaces` and in `npm-manifest.json` (`@fhevm/forge-std-dev` / `@fhevm/forge`), so
`node_modules` is the root's — `libs` and `remappings.txt` point at `../../node_modules`, never at a local
copy — and every verb has a `make` name: `compile-forge-std` (after `compile-cleartext-v-cur`, because the
payload is copied from `<vN>`), `lint-forge-std`, `test-forge-std`, and the opt-in `test-forge-std-fork`,
`-fork-url`, `-anvil`. `make generate` and `make clean-generated` run this package AFTER `<vN>`, so
`check-generated` proves the whole chain in the diagram of [FR-20](FR-20.md), and `make check-pre` grades the package.json,
scripts, lockfile and lint policy by the workspace rules ([the npm rules](../../../fhevm-npm/rules/README.md)). The published
payload has a consumer test (`test-consumer/esm`, [NR-54](../../../fhevm-npm/rules/entries/NR-54.md) there), and it is A FOUNDRY PROJECT, not a Node
script: `package.json` installs `@fhevm/forge` by name next to `forge-std` (a git dependency, pinned to the
tag this package vendors), `@fhevm/solidity` and `encrypted-types`; `remappings.txt` points every prefix into
`node_modules`; `src/AplusB.sol` is the dApp and `test/AplusB.t.sol` inherits `TestFhevm` to encrypt, run and
decrypt against it. `npm test` there is `forge build && forge test`. Its `foundry.toml` restates the `[fmt]`
policy inline rather than extending `foundry.base.toml` (a standalone project is copied out of the tree —
the one exception of [NR-30](../../../fhevm-npm/rules/entries/NR-30.md)), so `forge lint` and `forge test` work only after `npm install` in the copy.
